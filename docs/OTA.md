# Обновления Android без повторной установки APK

Один раз установите APK-загрузчики WolfCraft и WolfStudio поверх старых приложений. Идентификаторы пакетов и ключ подписи сохранены, поэтому миры и настройки остаются на месте.

- WolfCraft: кнопка «Обновить» в шапке лаунчера (на узком экране — круглая стрелка).
- WolfStudio: «Настройки» → «Обновить WolfStudio без APK». В редакторе доступна та же проверка из настроек игры.
- Проверка скачивает подписанные библиотеки, а не APK. После установки нужен перезапуск процесса; загрузчик предлагает его сам.
- Редактор и встроенный сервер обновляются одним проверенным пакетом.

## Доступ к закрытому GitHub

Обновления опубликованы в том же dozyFJ/WolfCraft, без публикации частного проекта наружу. Для закрытого репозитория в каждом приложении один раз вводится fine-grained GitHub token, ограниченный этим репозиторием и разрешением Contents: Read-only. Для публичного репозитория ключ не нужен. Ключ хранится в приватных данных приложения, не в APK, OTA-пакете или журналах. Авторизация не пересылается на домены хранения файлов при редиректе.

## Что обновляется

- `libwolfcraft_game.so`: игра, нативный лаунчер, GUI, встроенные текстуры, механики и Luau.
- `libwolfstudio.so`: Rust-редактор, инструменты студии, игровая часть.
- `libwolfserver_runtime.so`: ядро сервера и серверный Luau. Сервер работает через стабильный JNI API, а не через запуск скачанного исполняемого файла.
- Нужные нативные зависимости, включая `libc++_shared.so`, идут в том же пакете.

Java/Kotlin Android-оболочка, Android-дашборд WolfStudio, системные разрешения и SDK-настройки остаются частью APK. Их изменение требует нового APK. Это определяется автоматически по отпечатку исходников оболочки. Изменение формата сохранений также требует нового APK с проверенной миграцией; такой пакет не активируется поверх старого загрузчика. Большинство изменений Rust-ядра не затрагивает эти условия.

## Публикация

Обычный push в `mobile-explosives` собирает APK и OTA:

- `game-ota`: `game-ota.json`, `game-ota.sig`, `game-runtime.zip`.
- `studio-ota`: `studio-ota.json`, `studio-ota.sig`, `studio-runtime.zip`.

Отдельная ветка `codex/ota-launchers` публикует первые APK в `ota-bootstrap` / `studio-ota-bootstrap`, чтобы не заменять тестовые APK Claude во время разработки. После включения workflow в рабочую ветку новые сборки ядер публикуются автоматически.

`tools/build_ota.py` проверяет формат ELF64/AArch64 и обязательные экспорты ABI. Манифест подписывается RSA/SHA-256 тем же ключом, которым подписан APK. В приложение попадает только сертификат; закрытый ключ в OTA не включается. `tools/shell_hash.py` учитывает исходники Android-оболочки, но не Rust.

## Проверки и откат

Загрузчик проверяет подпись по сертификату установленного APK, приложение, архитектуру, API и отпечаток оболочки, формат сохранений, возрастающий номер сборки, SHA-256 архива и каждой библиотеки. Лишние файлы, дубликаты и пути вне каталога запрещены; общий размер ограничен.

Распаковка идёт в отдельную папку. Текущая версия переключается атомарно только после полной проверки, библиотеки сохраняются только для чтения. Миры, серверные конфиги, плагины и настройки OTA-код не заменяет. Перед открытием обновления из игры сохраняются открытый мир и скрипт студии.

Перед запуском нового ядра ставится отметка. После готовности окна/GPU или запуска сервера она снимается. Если процесс погиб до успешного старта, при следующем запуске восстанавливается предыдущая подписанная версия или встроенное ядро. Ручной откат доступен в окне обновлений. Это защита запуска, не отмена любых изменений игрового мира после длительной игры.

## Проверка на устройстве

CI проверяет сборки APK и ABI, JVM-тесты проверяют подписи и распаковку. Нужна дополнительная проверка на реальном arm64 Android: установка загрузчика, первый запуск, обновление на следующий commit, перезапуск, вход в сохранённый мир, запуск/остановка сервера и откат. Наличие успешной сборки само по себе не подтверждает поведение Android linker/NativeActivity на конкретном телефоне.
