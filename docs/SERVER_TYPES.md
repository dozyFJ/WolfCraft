# Обычные миры и плейсы

Один WolfServer и один протокол обслуживают два профиля создания мира.

| Профиль | Новый мир | Режим по умолчанию | Мини-игры |
| --- | --- | --- | --- |
| Обычный | Планета с природой | Выживание | Выключены |
| Плейс | Пустая Baseplate | Творческий | Разрешены в студии и по сети |

WolfStudio → «Создать мир или плейс» предлагает оба профиля. Они хранятся в общей папке `wolfserver/worlds`, но у каждого собственный уникальный ID и `world.toml`.

ПК:

```sh
WolfServer --name "Мир друзей" --planet
WolfServer --name "Мой плейс" --place
WolfServer --world <id>
```

Без флага создаётся обычная планета. `--creative` и `--survival` переопределяют режим только нового мира. Существующие миры сохраняют профиль, seed и режим независимо от флагов запуска. `--world` открывает существующий ID и сообщает об ошибке, если он отсутствует; повреждённый `world.toml` не перезаписывается.

API `/api/status` возвращает `world_id` и `kind` (`world` или `place`). Это метаданные мира, не отдельный протокол.

## Раздельные серверные окружения

Обычный сервер использует свою папку данных:

```text
wolfserver/
  server.toml
  core/
  plugins/<id>/plugin.toml
  plugins/<id>/main.lua
  modules/<id>.lua
  data/<id>.json
  worlds/<world-id>/world.toml
```

У каждого плейса отдельное окружение в его папке:

```text
worlds/<place-id>/
  world.toml
  place.toml
  server.lua
  script.lua
  core/
  plugins/
  modules/
  data/
```

`server.toml` обычного сервера не загружается в плейс. Плейсы не делят плагины, модули, ключи и данные друг с другом. `script.lua` остаётся клиентским сценарием; `server.lua` выполняется на WolfServer. Встроенное Rust-ядро и протокол общие; входной серверный скрипт ядра можно задать отдельно для каждого окружения.

При первом запуске создаются конфиг и папки. Пример настроек (настоящий ключ создаётся автоматически):

```toml
version = 1
core = "builtin"
max_players = 16
owner_key = "НЕ ПУБЛИКОВАТЬ: случайный ключ из 64 символов"
editor_keys = []
plugins = []
```

Для своего скрипта ядра укажите `core = "core/main.lua"`. Активные плагины перечисляются явно: `plugins = ["welcome"]`. Неизвестные поля и неверный конфиг останавливают запуск, а не сбрасывают настройки.

`plugins/welcome/plugin.toml`:

```toml
id = "welcome"
entry = "main.lua"
modules = ["greeting"]
```

`modules/greeting.lua`:

```lua
return { text = "Добро пожаловать!" }
```

`plugins/welcome/main.lua`:

```lua
local greeting = require("greeting")
on("join", function(player)
    server.broadcast(player.nick .. ": " .. greeting.text)
    store.set("last_player", player.nick)
end)
```

Модули загружаются из `modules/` своего окружения и кэшируются отдельно в каждой VM. Циклический `require` выдаёт ошибку. Данные каждого плагина сохраняются в собственном JSON; `store.get(key)` возвращает строку или nil, `store.set(key, value)` принимает строки. Клиентские скрипты к этому хранилищу доступа не имеют.

## Серверный Luau API

События: `start`, `stop`, `tick` (`dt`), `join`, `leave`, `chat`, `block_edit`. Данные игрока содержат `id`, `nick`, `role`. Возврат `false` из обработчика `chat` или `block_edit` отменяет стандартное действие.

- `server.broadcast(text)`, `server.log(text)`, `server.kick(id, reason)`, `server.players()`.
- `world.get(face, i, j, k, hell?)` возвращает числовой ID блока, включая исходный рельеф.
- `world.set(face, i, j, k, block_id, hell?)` сохраняет изменение и рассылает его клиентам.
- `require(id)` загружает модуль; `store.get/set` сохраняет данные расширения.

У VM ограничение памяти 16 МБ, бюджет вызова 15 мс и максимум 256 правок за событие. Ошибка отключает расширение и пишет причину в журнал; при отключённом расширении клиентские правки блокируются до исправления и перезапуска. Скрипты не имеют произвольного файлового доступа. Загрузка и смена расширений пока выполняются файлами с перезапуском, без графического менеджера.

## Роли и подключение

Роль определяется ключом, не ником:

- `owner`: ключ владельца своего окружения.
- `editor`: один из ключей `editor_keys` своего окружения.
- `player`: обычное подключение без ключа.

В плейсе клиентские правки разрешены владельцу и редактору. Игрок взаимодействует с игровой логикой; произвольные пакеты изменения блоков сервер отклоняет и возвращает правильный блок. В обычном мире правки игроков разрешены, но могут быть отменены серверным плагином. Полной серверной симуляции выживания, инвентаря и мобов пока нет.

WolfStudio на своём телефоне получает временный ключ владельца из приватного приложения сервера. Для удалённого редактора предусмотрено подключение вида `адрес:порт#ключ` (ключ не является обычным кодом приглашения). Не передавайте такой адрес игрокам. Текущий TCP-протокол не шифруется; управление ключами через интерфейс и защищённый транспорт остаются отдельной задачей.

## Оставшиеся ограничения

Редакторские региональные сохранения и сетевой журнал правок требуют отдельной проверки публикации готового офлайн-плейса. Серверные расширения не заменяют полную авторитетную симуляцию игрового мира. Нативные бинарные плагины и подмена скомпилированного Rust-ядра не реализованы: расширения и входные скрипты ядра сейчас на Luau.
